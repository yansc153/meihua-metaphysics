# 玄学板块架构

状态：合并计划。canonical 仓库是 `yansc153/new-huajiao-shortline`。起卦实现留在独立的 Python 服务里。本文只划边界。

## 层

| 层 | 落点 | 允许做的事 |
|---|---|---|
| 数据采集 | 现有 Rust collector | 把上游原文和未解释的开收盘写入库 |
| 起卦核心 | 新的 Python HTTP 服务 | 时间卦、开收盘数字和、体用五句、起势收势、变盘标记 |
| 查表 | JSON 文件，由 Python 读取 | 64 卦 × 6 个动爻的规则格；齐济 64×64 文句另表，缺句就空着 |
| 回测 | Python 离线命令 | 命中率、时间切分、除权日清单。不在页面请求路径上 |
| API 网关 | 现有 Axum `api::router()` | 鉴权、配额、组装请求、校验 JSON 后送回。失败换成没有卦名的 unavailable 信封 |
| 页面 | React | 美股日频、问事。未登录或订阅无效显示锁；Python 失败显示不可用；单格没有上一场印价显示缺价 |
| 闸门 | 订阅闸门；问事配额 | 无会话 401，无有效订阅 403，配额用尽不再起卦 |
| 部署 | Mac mini 上的 Docker Compose | `meihua` 只在 compose 网络内，不单独挂到公网 |

Rust 不计算卦、不选择体用、不拼断语。Python 不发 cookie、不查订阅、不决定页面是否上锁。

## 数据流

日频，美股：

1. 页面请求 `GET /api/us/metaphysics/daily?session=YYYY-MM-DD`。
2. 订阅闸门先拦。不过闸的请求到不了 Python。
3. `session` 是目标美股交易日。传入的日子若休市，先改到下一场实际开盘，农历跟着那天。指数时间卦不用价格。板块、商品 ETF 和 AI 分组只用该日之前上一场的不复权开盘、收盘字符串，不用目标日当天的开收盘。
4. v1 这些字符串由 Python 读自己的日线 CSV。Axum 不从 `us_index_daily` 取开盘，也不调用 Yahoo 或新浪去补。Axum 只把交易日和美股允许列表交给 Python `POST /v1/cast/daily`。允许列表由网关写定，A 股和 `g=cn` 不在里面。Python 只给列表中的代码起卦。
5. Python 返回每个标的的本卦、动爻、起势、收势、断语、旺衰、变盘标记、互卦名。开盘或收盘缺失、为零或不是有限数时，该格 `status` 为 `missing`，档位是「缺价」，不把 0 送进余数。其他有印价的格仍返回。
6. Python 不可达、超时或返回非法 JSON：Axum 回 HTTP 200 和现有 unavailable 信封，正文里没有卦名。成功时只透传已校验的 JSON。Axum 不解释五行，也不补卦。

问事：

1. 页面提交代码、事项短文、起卦时间。
2. 闸门通过后，Axum 用登录邮箱锁住 Asia/Shanghai 当日的配额行。未满 3 次才占一个名额并调用 Python。空字段、不在美股允许列表里的代码、A 股代码在占名额之前失败，不调用 Python。
3. Python 返回形状完整的时间卦，这次占位才提交。4xx、5xx、超时、缺字段则回滚占位，不计数。
4. 计数写在 Postgres。Python 接口没有用户 id。配额在上海时间午夜归零。

回测不走这条路径。它读 `data/2026_us_daily.csv` 或以后的库内日线，在 Python 里出报告。

## 模块边界

- 指数（标普）只用时间卦：农历年支在正月初一更换，月和日用农历，时辰固定巳时，数是 6。纳指与标普同农历日、同巳时则同卦，页面只展示标普一张指数卡。
- 板块 ETF 和商品 ETF 在同一组板块格里。AI 分组是另一组美股代码。两者都只用上一场印价的开收盘数字和。高低价和成交量不进公式。
- A 股代码不进入板块板，也不进入 AI 分组，也不进入问事。A 股导航下不渲染玄学板块格。
- 变盘日：起势和收势分处偏多侧（偏多、略偏多）与偏空侧（略偏空、偏空）。任一侧是震荡则不是变盘日。
- 旺衰只用目标交易日的节气月建，标体当令、体失令或体中。变体 B 关闭，不改档位。
- 互卦只可显示卦名，不另出一档。v1 日频格显示这个卦名。
- v1 不做盘中改卦、不用成交量起卦、不做周卦。时间卦的公式不要求铺满 384 种一爻动。

## 和现有花椒表的衔接

`us_index_daily` 只有 SPX、IXIC、DJI 的收盘和涨跌幅，没有开盘。Yahoo 合同 `YF-01` 未接线。`ml_bars` 里的 Yahoo 直连是 4 小时线，不拿来做板块印价。v1 板块印价只在 Python 的日线 CSV。这份 CSV 当初从 Yahoo 日线收到分后写入，在线请求不再向 Yahoo 补价。第三位小数在这份文件里已经不存在。以后若由采集入库，用 migration `0060`，列只有 `trade_date`、`symbol`、`open_print`、`close_print`，没有卦名和档位。配额表单独用 `0059`。
